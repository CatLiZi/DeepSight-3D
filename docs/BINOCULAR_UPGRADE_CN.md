# 双目识别升级（2026-10-25）

原实现保留完整双目采集，但只对选中的一眼执行检测。现在每个处理周期使用同一个 USB MJPEG 帧，分别处理左右半幅；两侧都执行全画面检测，输出独立目标及处理状态。`tracking_eye` 只选择控制视角，不关闭另一侧检测。

## 当前数据流

3840×1080 原始 MJPEG → 解码一次 → 分眼及安装方向修正 → 左右独立检测/跟踪 → 保守外观关联 → 选择控制观察 → 原有目标策略和有界舵机纠偏。

- 每眼算法输入保持 1920×1080。SCRFD 共享同一 GPU 会话；跟踪框、灰度历史、嘴部历史、多尺度搜索及 MediaPipe 状态分别保存。
- 两眼每轮都执行全画面人脸检测；局部补查轮流执行，每眼间隔至少 0.36 秒。辅助身体模型每眼最多约 2.86 次/秒；跳过时不输出旧身体框。采集线程独立，只推理最新帧，避免排队积累延迟。
- 曝光、全图纹理和梯度用于诊断。近乎全黑/白或极平坦图像不参与目标选择；纹理分数不等于确定的遮挡分类或镜头质量。即使左图仍有纹理，只要右图有人脸，右侧观察也能进入选择。
- 暂存的 `_held` 框不进入双目控制候选。检测使用各眼自己的原始坐标，不直接平均两眼的像素位置。
- 跨目关联结合宽松位置/尺度约束、非身份识别的局部外观，以及双向唯一性和连续观察确认。相似多人、低纹理或不确定匹配保持分开；关联始终标记为“外观暂定”。同一目标没有通过关联时可能保留两个观察编号，尚不能保证多人跨目身份稳定。
- 控制眼或候选目标变化时，至少等待三个不同处理帧且跨越 0.12 秒。视角变化清空视觉纠偏平滑、说话人锁定和 ASD 图像片段；旧片段不会混用两眼画面。两眼失效或图像超过 0.75 秒时停止使用视觉目标；切换确认、无可用控制眼及结果过期期间不发送新的自动运动。
- 此处“停止”表示不再计算/发送新的自动转向，同时取消平滑规划器尚未发送的轨迹；已经下发给舵机的定时动作仍可能完成。实物制动及机械顺滑度没有由本轮视觉测试验证。

## 原网页与 API

继续使用 `http://127.0.0.1:8010/`。上方左右画面显示检测框、暂定编号及每眼处理速度；下方大图显示当前控制视角，并说明选择或等待原因。原始双目和原像素清晰度辅助继续保留。

`VisionFrameResult` 增加 `eye_frames`、`eye_targets`、`binocular`、`control_eye` 和 `control_ready`。`FaceTarget.source_eye` 说明所属视角。HTTP/WebSocket 的 `visual` 输出两眼结果；`visual.capture.per_eye` 给出实际检测序号、处理帧数及每眼帧率，`binocular.sample_sequence` 标明成对采集帧号。眼图网页预览缩至不超过 960 像素宽，算法输入和原始记录保持原分辨率。

## 验证与边界

证据目录：`hardware_inventory/binocular-upgrade-20261025/`。包括新旧配置快照、回归结果、预热后真实采集与四路录音、真实模型加人工遮挡的离线回放、浏览器验证。

```powershell
python tools/validate_binocular.py --output ../hardware_inventory/binocular-upgrade-20261025
python tools/probe_runtime_capture.py --seconds 30 --output <新的输出目录>
python tools/probe_binocular_replay.py --source <已录制的双目JPEG> --output <新的输出目录>
```

测试脚本不打开舵机串口。离线遮挡回放只是对保存的真实样张施加数字遮罩，不代替实物遮挡或多距离/多人现场评测。全套历史失败单独对照先前记录，不将其描述为全部通过。

本轮没有双目内外参或精确物理坐标，不输出深度，也不把两个相机的归一化偏差视为同一标定角度。下一步需固定镜头及手动焦点，确认两幅画面与实物左右镜头对应，采集覆盖画面边缘、不同姿态和距离的已知尺寸标定板，并验证重投影误差、极线误差及已知距离。通过后才能启用空间方向融合和测距。

音频仍为 4 通道/48 kHz/16 bit RAW WASAPI；方向只使用左耳 CH3、右耳 CH2，身体 CH1/CH4 排除。Pitch 软件水平基准仍为 1553。
