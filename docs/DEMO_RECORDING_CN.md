# 双人对话演示录制 D1

网页“实时感知”新增“**双人对话演示**”。算法版本为 R52，录制功能版本为 D1。录制与“开始运行/停止”分别操作：录制按钮不会启用或转动舵机。

1. 两人都进入双目画面。A站小熊自身左前方，保持位置；B站右前方，在自己一侧缓慢横向移动。以能看清两人的脸为准，无需假定精确角度。
2. 操作者确认摄像头和两轴反馈；两人轮流说话演示选择“听声转头 · 声音主导”。它与“视觉跟踪”互斥，转向声源后由视觉修正，新声源可以打断旧的人脸跟随。确认后开始运行。
3. 点击“录制60秒”，在浏览器弹窗中选择**控制台所在标签页**。录制开始后有3秒准备；英文对话与逐段提示在页面内，也见 [英文对话稿](DEMO_DIALOGUE_EN.md)。
4. 结束后等待“录制已保存”，下载 MP4 或全部材料 ZIP。可用“查看最近已保存材料”重新取得上一轮文件。

## 材料与时间轴

- 网页画面由浏览器 `getDisplayMedia` 和 `MediaRecorder` 采集；每次都需要操作者选择共享标签页。
- 声音由后台工作线程读取**已有** WASAPI RAW 采集历史，原始四路仍保存为 48 kHz / 16-bit WAV。MP4使用配置中的左右耳通道作立体声；当前是 CH2 / CH3。
- `timeline.jsonl`保存网页收到的目标编号、候选匹配分、声源方向、指令位置、实测反馈及对话提示。A/B按钮是观察者标记；计划提示与算法识别结果各自记录。
- 视频和音频使用软件时间戳对齐，生成最长60秒的H.264/AAC MP4。同步元数据保存在 `session.json`；该对齐没有标定屏幕首帧、曝光和ADC的真实延迟，不宜直接用来报告精密端到端延迟。
- 音频缓冲的已知缺块会补零并记录数量；输入格式改变、断流或重新连接会结束这次声音录制。界面保留原材料下载入口，并说明异常。

本机目录为 `recordings/demo/<录制编号>/`。录制文件含现场人脸与声音，已由Git忽略规则排除，**不会随代码自动上传**。公网发布仍应另行审核。

## 失败与恢复

在选择标签页的弹窗中取消，不会开始录音。录制最长60秒，后台另有时限保护；共享结束、停止按钮和重复点击都按同一次结束处理。上传失败时页面保留原WebM下载和重试入口，后台保留已完成的四路WAV；视频生成失败也保留原材料。

录制中请保持标签页可见，并等待保存完成再刷新或关闭。正常退出服务会先结束录音；强制结束进程可能留下未完成材料，重新打开页面不会把它误标为完成。

需要Chrome/Edge桌面浏览器与本机FFmpeg/FFprobe。当前录制只显示网页和机载视角；若要展示小熊外观如何转动，可同时用手机从外侧拍摄。

## 验证范围

已用模拟采集与执行器验证四路WAV、缺块/重复块/时钟重置、自动结束、跨来源拒绝、上传大小限制和路径限制；用合成画面与已知四路正弦信号实际生成MP4，检查两路回放通道、前导静音与ZIP内容。浏览器界面已经模拟预览，真实的标签页授权、两人讲话和实物跟随仍由现场录制确认。

技术依据：[W3C屏幕采集规范](https://www.w3.org/TR/screen-capture/)、[FFmpeg文档](https://ffmpeg.org/ffmpeg.html)、[音频延时与裁剪过滤器](https://ffmpeg.org/ffmpeg-filters.html)。

本次文案为 A→B→A 三段较长发言，共90词；A不移动，B在自己的发言期间缓慢移动。网页按3–20秒、21–38秒、39–54秒提示，换人间隔1秒，最后保留6秒安静观察。计划时间线使用 three_turns_v2_A1 / B1 / A2 标识，完整内容见英文文案；计划标识不是实际讲话真值。
