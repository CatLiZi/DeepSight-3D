# R53：回中与手动动作控制权修复

日期：2026-11-05。R53保留R52互斥听声/视觉主模式、四麦与双目算法、D1录制和现有舵机行程。本次只修复控制权限和回中入口。

## 复核结果

现场已有日志显示，回中请求的目标确实为Yaw 2000、Pitch 1550，随后两轴反馈仍停留在此前位置附近；未见该次请求的目标值计算错误。离线复现进一步确认：R52后台感知在自动跟随已经暂停后，仍会因声源上下文/编号变化或视觉辅助目标丢失而调用轨迹取消，把刚提交的手动目标撤销。

这同时影响回中、方向键和手动姿态。原来只检查“停止后不再发新的自动动作”的测试不够，还需要检查“停止自动控制后，后台感知不能撤销新的手动动作”。

## 已修改

1. 所有感知驱动的轨迹取消统一通过`DemoRuntime._cancel_automatic_trajectory()`：仅当自动控制仍在运行、控制代次仍匹配时，才有权限撤销当前自动轨迹。
2. 暂停期间音视频分析继续，声音编号变化、声音到来、预览人脸出现/丢失不再取消手动运动。
3. 新增`POST /api/head/center`，由后端读取已保存中位，先核对两轴当前位置，再提交平滑回中目标。网页不再把缓存的中位数值当作归中依据。
4. 顶部“回中”、方向盘中点及居中预设共用同一前端入口；请求等待期间合并重复点击。
5. 前端仅提示“回中目标已提交”，不会把已发送指令表述为实物已经到位。
6. 增加`manual_center`、`manual_center_error`和带原因的`auto_trajectory_cancelled`日志，便于区分收到目标、取消原因与实际反馈。

## 保留的保护和参数

- 停止按钮、反馈故障、越界、模式变化仍可以撤销运动；迟到请求不能覆盖较新的控制意图。
- 听声模式中，新确认声源仍可打断正在运行的视觉辅助；视觉模式的稳定跟随未改变。
- Yaw范围1500–2500、中位2000；Pitch范围1255–1855、中位1550。
- 50Hz五次轨迹、速度180、加速度600、jerk3000的配置不变，单位为位置刻度及其时间导数，不是角度。
- 模型、阵列通道、声学参考1952、刻度/角度比例、相机标定与Blender几何均未修改。

## 后续现场复核顺序

正常退出旧服务并运行`python -X utf8 ./run_server.py`，网页Ctrl+F5刷新，确认显示R53。先不启动自动跟随，只点一次回中；观察头部到达正前方且水平，并用位置反馈核对接近2000/1550。然后分别测试手动上下/左右、Stop，最后重新开启听声或视觉模式。

如果仍失败，保存回中请求时间与错误记录编号；核对`manual_center`是否存在、是否出现`auto_trajectory_cancelled`、位置反馈是否有效。指令目标、规划位置和实际位置必须分别检查。
